# 開発・修正時の自己テスト必須規則 (Self-Testing Mandate Rule)

## 概要
コード、HTML、JavaScript、データ構造の修正を行った場合は、変更完了をユーザーに報告する前に、**必ず自身で動作・描画・構文の検証（自己テスト）を実行し、問題なく動作することを確認しなければならない**。

## 必須検証ステップ

### 1. HTML / JavaScript (UI) の変更時
- **構文検証**: Node.js の `vm` モジュールや構文解析器を用いて JavaScript コードに文法エラー（Undefined変数、SyntaxError等）がないかテストすること。
- **DOM描画検証**: 実際のDOMコンテナ (`councilList`, `meetingsList`, `ministryListContainer` 等) にデータが想定通りレンダリングされるか、ロジックを実行して確認すること。
- **データロードの動作検証**: HTTP 404や静的ファイル読み込み時（ローカル環境/サーバー環境）のフォールバック処理を含め、配列やデータが空にならないか検証すること。

### 2. データ構造・JSON の変更時
- JSONの形式（オブジェクトか配列か）の整合性を確認すること。
- `docs/data.js` などの定数ファイルへの同期後、Node.js 環境で実行してロードできるか検証すること。

## 禁止事項
- テストを実行せずに「修正完了」をユーザーに報告してはならない。
- エラーの仮説のみで修正を行い、動作確認を行わずに報告してはならない。
