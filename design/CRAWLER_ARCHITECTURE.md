# 政策会議ウォッチ (PM-HUB) クローラー仕組み・技術アーキテクチャ仕様書

本ドキュメントは、「政策会議ウォッチ (PM-HUB)」において、分散する日本政府各省庁の審議会・諮問会議・配布資料をどのように自動巡回・抽出・構造化しているかの仕組みを解説する技術仕様書です。

---

## ⚙️ 2. クローリングの具体的なステップと仕組み

### Step 1: ターゲット構成の定義 (`CRAWL_TARGETS`)
[admin/crawler.py](file:///d:/dev/PMHub/admin/crawler.py) の `CRAWL_TARGETS` 配列にて、巡回対象の省庁コード (`CAO`, `CAS`, `DIGITAL` 等)、会議体名、公式URLを集中管理しています。

```python
CRAWL_TARGETS = [
    {
        "id": "cas-zensedai-hosyo",
        "ministry": "CAS",
        "name": "全世代型社会保障構築会議",
        "url": "https://www.cas.go.jp/jp/seisaku/zensedai_hosyo/index.html"
    },
    {
        "id": "cao-ai-hq",
        "ministry": "CAO",
        "name": "人工知能戦略本部",
        "url": "https://www8.cao.go.jp/cstp/ai/ai_hq/kaisai.html"
    },
    ...
]
```

---

### Step 2: HTTP リクエスト & エラー制御 (`fetch_page`)
- **User-Agent の偽装・適合**: 政府Webサーバーからの不要な拒否（403 Forbidden）を避けるため、標準的なブラウザ識別子（`Mozilla/5.0...`）を送信します。
- **タイムアウト & ステータス検証**: リクエストごとに10秒のタイムアウトを設定し、`HTTP 200 OK` を確認します。リンク切れ（`404 Not Found`）やネットワーク障害発生時は安全にスキップしてログを記録します。

---

### Step 3: 文字コード自動判別・HTMLデコード
政府機関のWebサイトでは、作成時期や省庁により文字コード（`UTF-8`, `Shift-JIS / CP932`, `EUC-JP`）が混在しています。
取得したレスポンスの Header および Content-Type から以下のように優先順位をつけて自動デコードします：

1. `Shift-JIS` / `CP932` （古い政府PDF目録・内閣官房一部ページ）
2. `UTF-8` （デジタル庁・内閣府最新ページ）
3. `EUC-JP` （一部の専門審議会アーカイブ）

---

### Step 4: メタデータの抽出・解析ロジック (`extract_metadata`)

#### A. 開催年月日（和暦・西暦）の標準化
HTML本文中から正規表現（Regex）を用いて日付表記を検出します。
- **パターン1 (和暦)**: `令和([0-9０-９一-九]+)年([0-9０-９一-十二]+)月([0-9０-９一-三十一]+)日`
- **パターン2 (西暦)**: `(20[2-9][0-9])年([0-1]?[0-9])月([0-3]?[0-9])日`

和暦表記（例: `令和8年7月30日`）は、内部で `令和年 + 2018 = 2026年` として計算し、**`2026-07-30` (ISO 8601フォーマット)** へ正規化します。

#### B. 一次ソース資料（PDF / HTML）の絶対パス復元
Webページ内でリンクされている配布資料（議事次第、議事要旨、議事録、答申PDF）の href 属性を取得します。
- 相対パス表記（例: `./dai21/gijiroku.pdf` や `../pdf/konkyo.pdf`）を検出した場合、`urllib.parse.urljoin(base_url, href)` を使用して、ブラウザで直接アクセス可能な**完全な絶対URL (`https://...`)** に変換します。

---

### Step 5: 結果の出力と公開ポータルへの反映

1. **管理用ログ出力 ([admin/scraped_councils_output.json](file:///d:/dev/PMHub/admin/scraped_councils_output.json))**:
   巡回日時、全対象サイトの接続結果 (200 OK件数)、抽出された資料PDFの全リストをJSON形式で記録します。

2. **公開ポータルへの同期 ([docs/data.js](file:///d:/dev/PMHub/docs/data.js))**:
    検証完了後、`docs/data.js` の `MEETINGS` 配列へメタデータが組み込まれ、検索・フィルター・エクスポート機能ですぐに利用可能になります。

## 🤝 3. 紳士的クローリング (Polite Crawling) ポリシー

日本政府サーバーへの過度な負荷（DoS行為）を防ぎ、安定して情報を取得するため、以下のポリシーを厳守しています：

1. **アクセス間隔の確保**: リクエスト間に `time.sleep(1.0)` 以上のウェイティングを挿入。
2. **無駄な転送の削減**: 大容量のPDFファイル本体はダウンロードせず、**メタデータ（URL・タイトル・サイズ）のインデックスのみを収集**。
3. **エラーハンドリング**: 404/500エラー発生時は無限ループや無駄な再試行を行わずログ記録してスキップ。
