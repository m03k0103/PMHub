# 政策会議ウォッチ (PM-HUB) - AIエージェント クロール・データ更新作業手順書 (Agent Crawl Guide)

本規程は、AIエージェント（Antigravity Agent）が日本の中央省庁の審議会・検討会Webサイトをクロールし、`docs/data.json` およびスクレイピングルールを更新・保守する際に必ず遵守すべき標準作業手順です。

---

## 1. クロール・データ更新の基本原則 (Core Mandates)

1. **データ構造の正確性**: `docs/data.json` の `councils` と `meetings` 配列のデータ構造・JSON文法エラー（SyntaxError）を100%防止。
2. **回次表記の明確化**: 会議タイトルは後続の「最新会合」などの汎用表記を避け、「`第X回`」または「`令和Y年度第Z回`」と具体の回次を明記。
3. **資料データの末端取得**: 会議資料は中間ページリンクではなく、各回の「提出資料」「配付資料」ページを辿り、末端のPDF/HTMLリンクを直接取得して `materials` 配列に登録。
4. **非公開・手交資料の完全記録**: 一次ソースページに【非公開】・【手交】として掲載されている資料も漏れなく `materials` 配列に記録し、透明性を担保。
5. **却下・除外対象会議体の再追加防止**: ユーザー指定により却下された会議体（`admin/rejected_councils.json` に登録された会議体）はクロール対象から完全に除外、`data.json` へ復帰・再追加しない。
6. **同一資料リンクの重複防止**: 会議体の内部で複数開催回にわたって同一URLを重複紐付けしないよう、過去の開催回との重複を確認・排除。
7. **同一省庁への連続アクセス回避**: 政府Webサーバーへの過度な負荷集中を防ぐため、クロール対象の会議体リストは省庁単位でグループ化し、各省庁から1件ずつ交互に巡回するインターリーブ巡回を実施。
8. **唯一のデータソースの原則**: 中間データファイル等は使用せず、すべての会議体データ・開催回データ・設定は `docs/data.json` に直接反映・集約管理。

---

## 2. クロール実行手順 (Step-by-Step Procedure)

### Step 1: ルールの事前確認 (`docs/data.json`)
- クロール対象の会議体ID、URL、抽出ルールが `docs/data.json` の `councils` および `scrapingRules` に正しく定義されていることを確認。

### Step 2: クローラーの実行
- ターミナルより `admin/crawler.py` を実行：
  ```bash
  cd admin
  python crawler.py
  ```
- 実行結果（各開催回および配付資料リンク、`crawlStatus`、`lastCrawlTime`）が `docs/data.json` に直接保存されます。

### Step 3: 自動テストによる検証
- データ更新後は必ず以下のテストを実行し、エラーが0件であることを確認：
  ```bash
  python testing/smoke_test.py
  node --test testing/app.test.js
  ```
